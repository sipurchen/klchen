# Specification: Token Bucket Rate Limiter

## 1. Project Overview
The goal is to implement a lightweight, thread-safe rate-limiting utility for a Python API client. The limiter will control the frequency of outgoing HTTP requests to ensure the client stays within the bounds of a provider's rate limits, preventing `429 Too Many Requests` errors.

## 2. Objectives
*   **Burst Support:** Allow a defined number of immediate requests if the "bucket" is full.
*   **Steady-State Regulation:** Enforce a consistent long-term request rate.
*   **Non-blocking/Blocking Options:** Provide a way to either check availability (to skip a task) or wait (to delay a task) until a token is available.
*   **Thread Safety:** Ensure that multiple threads using the same client instance do not over-consume tokens.

## 3. Core Algorithm Logic
The implementation will track two variables:
1.  **Current Token Count:** The number of tokens available in the bucket.
2.  **Last Refill Timestamp:** The last time the bucket was updated.

Upon every request attempt, the system will calculate the elapsed time since the `last_refill_timestamp`, calculate how many new tokens should have been added based on the `refill_rate`, and update the `current_token_count` (clamping it at the maximum `capacity`).

## 4. Interface Definition

### `TokenBucket` Class

#### `__init__(capacity: float, refill_rate: float)`
*   **Inputs:**
    *   `capacity`: The maximum number of tokens the bucket can hold (allows for bursts).
    *   `refill_rate`: The number of tokens added to the bucket per second.
*   **Internal State:** Initializes `current_tokens` to `capacity` and sets `last_refill_time` to the current system time.

#### `consume(amount: float = 1.0) -> bool`
*   **Description:** Attempts to remove a specific number of tokens from the bucket.
*   **Inputs:**
    *   `amount`: The number of tokens required for the operation (default is 1).
*   **Outputs:**
    *   `True`: If tokens were successfully deducted.
    *   `False`: If there were insufficient tokens (the bucket is empty).

#### `wait_for_token(amount: float = 1.0)`
*   **Description:** A blocking method that pauses execution until enough tokens are available.
*   **Inputs:**
    *   `amount`: The number of tokens required.
*   **Outputs:**
    *   `None`: Returns once the bucket has been replenished enough to satisfy the request.

#### `available_tokens() -> float`
*   **Description:** Returns the current number of tokens available in the bucket (after calculating the most recent refill).
*   **Outputs:**
    *   `float`: The current token count.

## 5. Constraints & Edge Cases
*   **Time Drift:** Use `time.monotonic()` instead of `time.time()` to ensure the limiter is immune to system clock updates/drifts.
*   **Concurrency:** Use a `threading.Lock` to wrap the refill and consumption logic to prevent race conditions in multi-threaded environments.
*   **Floating Point Precision:** Refill rates and capacities should support floats to allow for granular control (e.g., 0.5 tokens per second).<turn|>

import time
import threading

class TokenBucket:
    """
    A thread-safe implementation of the Token Bucket algorithm for rate limiting.
    """

    def __init__(self, capacity: float, refill_rate: float):
        """
        Initialize the bucket.

        :param capacity: The maximum number of tokens the bucket can hold.
        :param refill_rate: How many tokens are added to the bucket per second.
        """
        if capacity <= 0 or refill_rate <= 0:
            raise ValueError("Capacity and refill_rate must be positive values.")

        self._capacity = float(capacity)
        self._refill_rate = float(refill_rate)
        self._tokens = float(capacity)
        self                = time.monotonic()
        self._last_refill_time = time.monotonic()
        self._lock = threading.Lock()

    def _refill(self) -> None:
        """
        Internal method to update the token count based on elapsed time.
        Must be called while holding the lock.
        """
        now = time.monotonic()
        elapsed = now - self._last_refill_time
        
        # Calculate new tokens earned since last update
        new_tokens = elapsed * self._refill_rate
        
        # Update bucket, ensuring we don't exceed capacity
        if new_tokens > 0:
            self._tokens = min(self._capacity, self._tokens + new_tokens)
            self._last_refill_time = now

    def consume(self, amount: float = 1.0) -> bool:
        """
        Attempts to consume a specific number of tokens.

        :param amount: Number of tokens to consume.
        :return: True if successful, False if insufficient tokens.
        """
        if amount > self._capacity:
            return False

        with self._lock:
            self._refill()
            if self._tokens >= amount:
                self._tokens -= amount
                return True
            return False

    def wait_for_token(self, amount: float = 1.0) -> None:
        """
        Blocks execution until the required number of tokens are available.

        :param amount: Number of tokens to wait for.
        """
        if amount > self._capacity:
            raise ValueError("Cannot wait for more tokens than the bucket capacity.")

        while True:
            with selfs._lock:
                self._refill()
                if self._tokens >= amount:
                    self._tokens -= amount
                    return
                
                # Calculate how long we need to sleep until enough tokens arrive
                needed = amount - self._tokens
                wait_time = needed / self._refill_rate
            
            # Sleep outside the lock to allow other threads to interact with the bucket
            time.sleep(wait_time)

    def available_tokens(self) -> float:
        """
        Returns the current number of tokens available after a refresh.

        :return: Current token count.
        """
        with self._lock:
            self._refill()
            return self._tokens

### Key Implementation Details:
1.  **`time.monotonic()`**: Used for all time calculations to ensure accuracy even if the system time is manually adjusted during execution.
2.  **The `_refill` Pattern**: Instead of having a background thread constantly adding tokens (which is resource-heavy), this implementation uses a "lazy refill" strategy. It calculates how many tokens *should* have been added only when a method is actually called.
3.  **Thread Safety**: A `threading.Lock` protects the `_tokens` and `_last_refill_time` variables. This ensures that if two threads call `consume()` at the exact same microsecond, one will be processed before the other, preventing "double-spending" of tokens.
4.  **Smart Waiting**: In `wait_for_token`, the code calculates the exact `wait_time` required. It also releases the lock before calling `time.sleep()`. This is critical; if the lock were held during the sleep, no other thread could use the limiter, defeating the purpose of a multi-threaded client.
5.  **Complexity**: 
    *   **Time**: $O(1)$ for all operations.
    *   **Space**: $O(1)$ to store the state.<turn|>
